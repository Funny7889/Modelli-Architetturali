Architetture distribuite software

Che cos'è

Le architetture distribuite software rappresentano l'evoluzione dei sistemi informatici, attraverso diverse modalità di organizzazione e collaborazione tra computer e componenti software. Nel tempo si sono sviluppati diversi modelli architetturali, dai terminali remoti fino alle moderne architetture a microservizi.

Caratteristiche principali

  • Terminali remoti: tutte le operazioni sono eseguite da un'unica entità centrale. I terminali non hanno capacità di elaborazione e si limitano a visualizzare e inviare o ricevere informazioni.
  • Client-server: i client richiedono servizi a un server specializzato, che elabora le richieste e restituisce le risposte. Possono esserci più server e più client.
  • Web-centric: il web server è il centro del sistema. Tutta la computazione avviene sui server, mentre i client servono principalmente come interfaccia grafica.
  • Cooperativa: entità autonome esportano e richiedono servizi. Si basa sullo sviluppo a componenti e sulla programmazione a oggetti, con necessità di standardizzazione.
  • Completamente distribuita: entità paritetiche cooperano tra loro, offrendo e richiedendo servizi. Possono essere presenti servizi e dati duplicati per garantire l'immunità ai guasti.
  • A microservizi: l'applicazione viene suddivisa in componenti autonomi, ciascuno con una funzione specifica. I microservizi comunicano tramite API e ognuno possiede il proprio database.

Schema riepilogativo

Tappa Caratteristica principale Esempio
1. Terminali remoti Tutte le operazioni sono eseguite da un'unica entità centrale. I terminali sono omogenei e privi di capacità di elaborazione. Mainframe con terminali (sistemi bancari storici).
2. Client-server I client richiedono un servizio a un server che elabora e risponde. Client e server possono essere tecnologicamente diversi. Applicazione gestionale con database su server.
3. Web-centric La computazione avviene sui server, che restituiscono il risultato ai client. Gli host funzionano quasi come terminali stupidi. Applicazioni gestionali convertite al Web e siti web.
4. Cooperativa Entità autonome esportano e richiedono servizi. Si basa sullo sviluppo a componenti e sulla programmazione a oggetti. Componenti software che invocano servizi di altri componenti.
5. Completamente distribuita Entità paritetiche offrono e richiedono servizi. Sono possibili duplicazioni per garantire l'immunità ai guasti. Sistemi groupware.
6. A microservizi Applicazione suddivisa in componenti autonomi con funzioni specifiche, comunicazione tramite API e database indipendenti. App web di grandi dimensioni suddivisa in servizi indipendenti.

Un esempio reale

Un esempio di architettura distribuita a microservizi è un'applicazione web di grandi dimensioni suddivisa in servizi indipendenti.

Ogni microservizio svolge una funzione specifica, comunica con gli altri tramite API e possiede il proprio database, strutturato secondo le proprie esigenze. Questa organizzazione rende l'applicazione adatta a sistemi complessi e scalabili.

Domande e risposte

Terminale remoto vs client?

Il terminale non ha capacità di elaborazione: mostra e invia dati all'entità centrale. Il client ha capacità di elaborazione e richiede servizi a un server specializzato.

Perché nel Web-centric si parla di terminali stupidi?

Perché con lo spostamento delle applicazioni sul server la computazione avviene lì e i client servono quasi solo come interfaccia grafica verso l'utente.

Cos'è un microservizio e perché ha un proprio database?

È un componente autonomo con una funzione specifica, che comunica con gli altri tramite API. Ogni servizio ha il proprio database strutturato secondo le proprie esigenze, invece di un unico grande database condiviso.

Quali sono i vantaggi dei microservizi?

Modularità, indipendenza dei servizi e gestione flessibile dei carichi di lavoro. Per questo sono più adatti ad applicazioni complesse e scalabili.
